# Zen v0.1.0-beta.1

First public beta of Zen: an Android interface for AI coding agents running on your own Linux machine.

## Included

- Linux daemon binaries for `amd64` and `arm64`
- Signed Android `arm64-v8a` APK
- Codex, Claude Code, Cursor Agent, and Grok sessions
- Structured chat, full terminal access, pairing, file uploads, and session management
- Brain workspace with Host and Delegated Executor lifecycle
- Native Android terminal powered by the pinned Ghostty VT library
- `zen doctor` diagnostics and `zen setup` executor configuration

## Install

Download the daemon for your Linux architecture, the Android APK, and `SHA256SUMS` from this release.

```bash
sha256sum -c SHA256SUMS --ignore-missing
install -m 755 zen-linux-amd64 ~/.local/bin/zen  # or zen-linux-arm64
zen doctor
zen
```

Then expose the daemon origin, run `zen pair https://your-origin`, install the APK, and import the pairing QR/link in the app. See the [installation guide](../install-daemon.md) and [pairing guide](../connect-and-pair.md).

## Android identity

- Package: `com.daoleno.zen`
- `versionCode`: `1`
- ABI: `arm64-v8a`
- Signing certificate SHA-256: `C2:FC:5B:09:B3:86:92:EE:70:59:71:1F:E7:ED:B8:79:4C:E3:65:FE:1C:7A:06:AB:95:4E:5D:D1:BD:CD:A4:FD`

Android may ask you to allow installation from unknown sources or show a Play Protect warning. Obtainium users can track this repository's GitHub Releases; Zen does not include an in-app updater.

## Known limitations

- Linux host and Android arm64 only
- No iOS app, Play Store package, hosted relay, or in-app updater
- You must provide network reachability through a Tailnet, VPN, tunnel, or reverse proxy
- At least one supported AI CLI must already be installed and authenticated on the host
- Older development builds used another Android package ID and do not upgrade in place

Existing `~/.zen` daemon state is preserved when replacing the daemon binary. Android upgrades require the same package ID and signing certificate.
