# zen v0.1.0-beta.1

Public beta candidate notes. A local `scripts/stage-release.sh` run copies this file into the stage as `RELEASE_NOTES.md`. Copying into a stage is **not** a GitHub Release; Brain/maintainer publishes tags and release assets separately.

## Beta scope

| Piece | Supported in this beta | Not claimed |
| --- | --- | --- |
| Daemon host | Linux (`linux/amd64`, `linux/arm64` binaries or build from source) | macOS/Windows as first-class hosts |
| Mobile app | Android sideload (arm64-v8a) | iOS app, Play Store listing |
| Agents | One of Codex, Claude Code, Cursor Agent, or Grok on `PATH` | “Every executor works out of the box” |
| Network | Your Tailnet, reverse proxy, or tunnel | Hosted relay / zero-config NAT |
| Terminal | Native Ghostty VT on Android when `libghostty_vt.so` is in the APK | Guaranteed terminal on a bare clone without build/artifacts |

## Official Android signing certificate (public metadata)

Release sideload APKs published by the maintainer for this product line are signed with a certificate whose SHA-256 fingerprint is:

```
C2:FC:5B:09:B3:86:92:EE:70:59:71:1F:E7:ED:B8:79:4C:E3:65:FE:1C:7A:06:AB:95:4E:5D:D1:BD:CD:A4:FD
```

This fingerprint is **public** package metadata (not a secret). Compare it with the certificate of any APK you install before trusting it. Local debug-keystore builds will **not** match.

## Android sideload warnings

- Install only from a GitHub Release (or other channel you trust) published by the project maintainer.
- Android will warn about **unknown sources** / install from this source. That is expected for sideload.
- **Play Protect** may scan or warn on sideloaded APKs that are not on Play Store. Review the warning; verify the certificate fingerprint above and `SHA256SUMS` for the APK asset.
- There is **no Play Store** distribution and **no in-app update framework** in this beta.
- Package id is `com.daoleno.zen`. Older dev builds used `com.anonymous.zen`; uninstall the old package before installing if both would conflict on the same device.
- ABI: **arm64-v8a only** for release sideload APKs.

```bash
# After downloading the APK and SHA256SUMS from a published release:
sha256sum -c SHA256SUMS --ignore-missing
adb install -r zen-android-arm64-v0.1.0-beta.1.apk   # exact asset name may vary
```

## Linux daemon install

Assets are top-level release files (not nested under `bin/`):

| File | Arch |
| --- | --- |
| `zen-linux-amd64` | linux/amd64 |
| `zen-linux-arm64` | linux/arm64 |

Also published/staged: `LICENSE`, `NOTICE`, `TRADEMARKS.md`, `GHOSTTY-MIT.txt`, `SHA256SUMS`, `identity.json`, `RELEASE_NOTES.md`.

```bash
# Verify checksums
sha256sum -c SHA256SUMS --ignore-missing

# Install the matching arch
install -m 755 zen-linux-amd64 ~/.local/bin/zen   # or zen-linux-arm64
zen doctor
```

Build from source remains supported: see [docs/install-daemon.md](../install-daemon.md).

## Upgrade behavior

- **Daemon:** replace the binary; keep `~/.zen` state (identity, trusted devices, pairing tokens). Re-run `zen doctor` after upgrade.
- **Android:** same `applicationId` (`com.daoleno.zen`) and higher or equal `versionCode` can update in place when the **signing certificate matches**. A different certificate requires uninstall first. Changing package id (e.g. from `com.anonymous.zen`) requires a fresh install and re-pair.
- **Pairing:** existing trusted devices remain; re-pair only if you reset daemon identity or the phone’s device key.

## Obtainium / GitHub Release compatibility

- Preferred mobile update channel for sideload users who want GitHub-based checks: **Obtainium** pointed at this repository’s **GitHub Releases** (not Play Store).
- Release asset names should stay stable enough for Obtainium filters (`zen-android-arm64-*.apk` or the exact published APK name).
- This project does **not** ship an in-app updater; Obtainium (or manual download) is optional and user-controlled.

## Limitations (honest)

- No iOS distribution target in this beta.
- No Play Store, F-Droid listing, or auto-update service operated by zen.
- Native terminal binaries are not in git; strangers need a published APK with libs or a local Ghostty build (see [docs/android.md](../android.md), [docs/release-blockers.md](../release-blockers.md)).
- Docker remains an advanced path; prefer the host Linux binary so tmux and agent CLIs share the environment.
