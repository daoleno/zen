# Zen v0.1.0-beta.19

This beta contains the reviewed changes on `main` since `v0.1.0-beta.18`.

## What changed

- Unify the Codex model identity: the selected model is now the Codex Session
  model, the routed upstream model, and the Interface projection — one exact
  slug everywhere, with no hidden `gpt-5` compatibility model. Launch argv
  runs the selected model and a deterministic per-connection Codex model
  catalog (`model_catalog_json`, Codex `ModelsResponse` shape); the loopback
  `/v1/models` serves that shape too. Unknown gateway-only models fail closed
  for managed Codex instead of masquerading under another identity
- Add the Reasoning Effort picker to the native Model sheet: values come only
  from the daemon-owned per-model contract (e.g. Low/Medium/High/XHigh/Max
  where actually supported), the current value is the daemon override or the
  documented model default, compatible model switches preserve the effort, and
  unsupported clients/models hide the control entirely
- Router identity semantics: request models/efforts pass through unchanged
  (never a silent override); a daemon-admitted request identity converges the
  route binding, so a Codex `/model` change in the Terminal converges the
  Interface projection. During a pending Zen-initiated switch the binding wins
  for admitted requests
- Live Codex changes: the Codex TUI exposes no external mutation protocol
  (verified against codex-cli 0.147), so Zen-initiated model/effort switches on
  a live Session run a managed resume handoff (`codex resume <thread>` with the
  new identity), preserving thread history and the Zen Session. The activation
  reply reports the handoff state; a failed handoff is shown truthfully instead
  of claiming UI convergence
- Telegram-style Session multi-select with bulk Terminate: long-press enters
  selection mode, taps toggle, the top chrome becomes Cancel + count +
  Terminate with one confirmation, partial failures stay selected with an
  accurate summary, and the list long-press Model shortcut was removed

## Install

Download `zen-linux-amd64.tar.gz`, `zen-linux-arm64.tar.gz`, or `zen-darwin-arm64.tar.gz` for your host, plus the Android APK and `SHA256SUMS`. Extract the archive, install `zen` on your `PATH`, run `zen`, then create a pairing link with `zen pair https://your-origin`.

Apple Silicon support requires `tmux` (`brew install tmux`). The macOS binary is cross-built and should be treated as beta until it has completed broader real-device testing.

The iOS Preview is distributed through TestFlight at <https://testflight.apple.com/join/rTKCDzMt>, subject to Apple's beta approval and processing.
